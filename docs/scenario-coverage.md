# Scenario coverage

OminiCat ships a configurable **record a phrase → transcribe → generate text → synthesize → play a reply** path. It also ships streamed model text, bounded conversation primitives and manual interruption. It does **not** yet ship a continuously listening, incremental-ASR/chunked-TTS, automatic-barge-in voice assistant.

Read coverage at two levels together: what a person can do, and which transport, processor and lifecycle mechanisms make that interaction work. A frame type or extension interface is not proof that a complete interaction is implemented. **Implemented** below means shipped code with the named local fixture; **composable** means additional integration policy or an adapter is still required. Local provider fixtures are not live-service or acoustic validation.

## Run the shipped voice path

The [offline Studio example](../config/studio.yaml) exercises PCM energy events, transcript revisions and echo without a model service. A transcript typed into Studio is supplied text; it does not test ASR. The [voice example](../config/voice.yaml) configures the real five-stage provider path. Configure the endpoint, models and credential environment-variable reference before making external calls; account/model availability is separate from factory preflight.

```sh
./mvnw -Pcoverage,sbom verify
java -jar ominicat-server/target/ominicat-server.jar --config config/voice.yaml
```

Open Studio, enter the debugger, connect explicitly, record a phrase, then stop and send it. The browser converts the completed recording to mono 16 kHz PCM and sends `turn_end`; it does not upload microphone chunks while recording. Capture is bounded to 15 seconds. The response text can arrive incrementally, but synthesized audio follows the completed text turn. See [configuration](configuration.md), [wire protocol](protocol.md) and [Studio controls](studio.md).

The ordinary verification command runs local fixtures without provider credentials. In particular, `ConfiguredVoicePipelineTest` uses actual sockets and three local HTTP endpoints to verify WAV input, prompt content, SSE text, PCM output, duplicate-final gating and cleanup. It does not contact a paid provider or certify what a real microphone and loudspeaker sound like.

## What streaming and interruption mean here

### Transcription and turn boundaries

`TURN_END`, `SPEECH_STOPPED` or `END` flush pending ASR tracks; no partial transcript is produced before that flush. Each nonempty stream produces a final segment with a stable session-local ID, revision zero and confidence `-1` when confidence is unavailable. Boundaries and other unconsumed frames then pass downstream. Track formats, sample cursors and attribution remain separate from speaker recognition.

`Transcript` and `transcript-gate` support revisable partials from a suitable adapter; carrying this data does not implement that adapter. The shipped declaration marks `TranscriptionFactory.UTTERANCE_FINALS` supported and `TranscriptionFactory.PRE_BOUNDARY_PARTIALS` unsupported. [Explicit capability checks](plugin-capabilities.md) can reject that mismatch before creation; default YAML/Studio startup does not enable the requirement check automatically.

Chat emits its own `TURN_END` after a valid SSE completion marker. A boundary from upstream can also pass through, so more than one boundary can appear; an empty speech buffer does not synthesize the same reply again. An application requiring one semantic turn-completion event must define that boundary rather than count raw controls.

### Synthesis and playback

Speech output is signed PCM16 little-endian, mono 24 kHz. The current `Audio` uses the default `streamId` and unknown `startSample`; it is not a sequence of timed synthesis chunks. A streaming TTS integration still needs explicit text segmentation, output chunk ordering/positions, buffering and cancellation rules. Merely receiving a provider response in several HTTP reads is not chunked audio delivery to the application.

Studio schedules received PCM through Web Audio, with a limit of 15 seconds of queued playback and 32 active sources; exceeding either stops local playback. These demo limits do not cancel remote effects or certify audible barge-in. Long synthesized responses can also exceed the WebSocket message/base64 budget. Align provider, message and playout limits, or supply a bounded chunked-output adapter; a successful HTTP request alone does not guarantee playable delivery.

### Conversation state and cancellation

`prompt-template` remembers only transcripts entering that stage; the linear pipeline does not loop assistant text back into it. Its history resets on interruption, while `transcript-gate` retains committed final identities inside its bounded retention window. An integration must choose which user and assistant facts remain committed after interruption. A snapshot API is not automatic reconnect recovery or a durable conversation store.

Session generation fences reject stale downstream emissions; they do not retract output already handed to a transport or revoke a provider request's completed effects. Scoped `Cancel` frames are application signals, not automatic request/turn ownership enforcement. Use the transport's implemented `interrupt` behavior where appropriate, with client playout cancellation and explicit external idempotency.

`END` is an application marker, not a barrier for independent delayed callbacks. For embedded asynchronous processing, `completion()` after `finish()` is the drain barrier. Providers must use finite deadlines, honor rejection/cancellation and release owned resources. Cooperative cancellation cannot guarantee termination of arbitrary Java code.

## Supporting abstractions and extension points

These mechanisms support specific interactions without requiring every integration to adopt one task state machine or one global media timeline.

| Mechanism | Shipped evidence | Remaining boundary |
| --- | --- | --- |
| Configured or embedded pipelines | [YAML/container setup](configuration.md), ServiceLoader factories, per-session processor ownership; typed direct and queued APIs. | A custom media/provider adapter must declare and verify its own formats, deadlines, state and resource limits. |
| Bounded transcript evaluation and steps | [Evaluation configuration](../config/conversation.yaml), [step configuration](../config/steps.yaml), [step fixtures](../ominicat-conversation/src/test/java/io/ominicat/conversation/flow/StepFlowProcessorTest.java), [evaluation fixtures](../ominicat-conversation/src/test/java/io/ominicat/conversation/ConversationEvaluatorTest.java). | Literal/punctuation rules are not semantic-model validation. Step definitions, policy meaning, storage and access control belong to the application. |
| Parallel work and slow destinations | [Parallel fixtures](../ominicat-core/src/test/java/io/ominicat/core/ParallelProcessorTest.java), [outlet fixtures](../ominicat-core/src/test/java/io/ominicat/core/AsyncOutletTest.java): bounded ordered synchronous branches and independent bounded delivery. | Current branch/fallback combinators reject asynchronous children. Async branches need separately owned sessions; durable acknowledgments, retries and idempotency remain external. |
| Replay and state restoration | [JSONL replay example](../examples/README.md), validated conversation/step snapshots and deterministic IDs/clocks. | The example replays transcripts, not long audio; decoding, utterance segmentation, file/sample cursors and job scheduling need a driver. |
| Optional source/annotation contracts | [Implemented T1a references](media-references.md); [temporal proposals](temporal-annotations.md) and [integration proposals](integration-contracts.md). | T1b editing, T2/T3 annotations/lifecycle and remaining I1/I2/I3 contracts are planned. They are not prerequisites for ordinary raw-frame voice pipelines. |

Media intervals need a common time basis only when an operation compares them. `startSample` is local to a source stream; the runtime does not infer device offsets or drift. Current evaluation excerpts preserve the whole turn's interval, not word-level audio alignment. Optional source references carry verified identities and mappings supplied by the integration; they do not provide a locator, decoder or correction service.

## Verification and remaining work

The concrete local evidence covers assembled ASR/chat/speech routing, partial/final data rules, multitrack buffering, SSE boundaries, full-response PCM, blocking-body cancellation, generation races, browser media cleanup and bounded overload. Browser control fixtures use a synthetic DOM/media environment; real device/browser acoustic behavior still needs target testing. [Synthetic performance reports](performance.md) do not measure recognition accuracy, speech naturalness, first-audio latency, end-to-end barge-in or production voice capacity.

The following order prioritizes a usable conversational loop, then hands-free input and live captions. These are integration candidates, not features delivered by this documentation update or automatically scheduled work. Select the smallest item required by the intended interaction; none requires a universal state machine, annotation suite or distributed platform.

| Priority / interaction | Smallest optional integration | Minimum acceptance |
| --- | --- | --- |
| 1 — Hear a reply before the complete model turn finishes | A bounded text segmenter plus speech adapter with an explicit PCM chunk/stream contract. | With a local model fixture holding its completion open and a speech fixture holding its body open, deliver the first valid audio chunk before both finish. Check chunk ordering/positions, bounded text/audio buffers, completion after accepted output, and cancellation without accepted stale audio. Do not infer an audible-latency guarantee from this fixture. |
| 2 — Remember both sides of a conversation | An explicit assistant-turn memory adapter or driver, with bounded message retention and an interrupted-reply commitment policy. | A second request contains the approved user and assistant turns exactly once. Failed/interrupted partial replies follow the declared policy; duplicates and truncation stay bounded. Plain text memory must not require fabricated media timestamps or a shared media timeline. |
| 3 — End an utterance without pressing Stop | A continuous PCM driver plus an optional per-stream endpoint/turn detector; reuse the ASR boundary already implemented. | Scripted speech/silence produces the declared boundary without losing/reordering PCM or repeatedly flushing one utterance; limits and interruption reset are tested. Automatic barge-in additionally requires a separately validated echo/playout decision and client stop path. |
| 4 — Read captions while speaking | A provider-native incremental ASR adapter using the existing partial/final revision boundary. | Emit a nonfinal transcript before the explicit boundary, continue accepting subsequent PCM, and finalize the stable segment correctly. Test revisions, rejection/deadline/cancellation and stream isolation against a local protocol fixture, then validate the explicitly configured target service. |
