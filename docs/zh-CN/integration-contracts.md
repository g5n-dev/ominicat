# 跨项目接入契约

状态：I1a 可选能力声明与显式要求检查已经实现，见 [API 指南](plugin-capabilities.md)。下述其余新增内容仍是设计提案与验收计划，不是可接受的 YAML 字段或新的运行时保证。更广的已实现范围仍以当前[场景矩阵](scenario-coverage.md)为准。

下一步接入目标是通过替换配置和插件，在流式事件处理、顺序重放与结果聚合适配器中复用同一个 Java 17+ 运行时。调度和生命周期留在微内核，可选兼容契约放在接入边界。每个实现增量都必须先有可执行的契约测试用例，才能对外宣称支持。

[时间／注释提案](temporal-annotations.md)定义可选的来源／区间、编辑、注释和依赖能力组合。最小来源／区间引用与二进制导入导出已经[实现](media-references.md)，其他能力仍在计划中。应为具体接入选择能力，而不是把它们视为强制技术栈。I1 发现机制相互独立，仅面向主体的注释无需媒体时间线，只读导入无需编辑归约器。I1/I2/I3 按需支撑兼容性、外部编码与恢复；能够承载一个事件不代表已经实现其语义。

## 当前机制与待补契约

| 领域 | 当前可由源码核实的行为 | 后续契约／负责方 |
| --- | --- | --- |
| 插件组装 | [ProcessorFactory](../../ominicat-core/src/main/java/io/ominicat/core/spi/ProcessorFactory.java) 保留 `type/create`；[PluginRegistry](../../ominicat-core/src/main/java/io/ominicat/core/spi/PluginRegistry.java) 发现工厂，拒绝重复或缺失的类型。I1a 新增按配置查询的可选能力声明及显式要求检查，不创建处理器。启动仍执行创建／关闭校验。 | 丰富选项 schema、输入／输出格式、媒体／时间契约及其余兼容性测试。能力声明不替代现有配置校验。 |
| 事件标识与时间 | [FrameEnvelope](../../ominicat-core/src/main/java/io/ominicat/core/FrameEnvelope.java) 携带事件／会话／轮次／关联／因果 ID 及本地单调时间戳。转写使用媒体毫秒，音频使用逐流采样偏移。 | 驱动负责归一化媒体时间线。关联 ID 仍是不可信数据，不是授权。不得比较独立时钟域。 |
| 结构化结果 | [EvaluationFrame](../../ominicat-conversation/src/main/java/io/ominicat/conversation/EvaluationFrame.java) 包含策略标签、规则结果、分数、证据及保留／淘汰范围。[自定义线协议输出](protocol.md#插件输出) 使用 Java 简单类名，已明确不具备稳定的全局 schema 命名空间。 | 可选、显式注册且带命名空间的结果 codec。这是扩展已经承认的边界，不是修复一个曾声称稳定的协议。 |
| 证据 | [Evidence](../../ominicat-conversation/src/main/java/io/ominicat/conversation/Evidence.java) 包含片段、角色／说话人、媒体区间和复制的摘录；内置规则限制其生成摘录。自定义证据生产者自行负责限制。已提交最终片段在保留窗口内不可变。 | 面向外部消费者的可选来源／修订／运行引用。最终结果的更正与撤回策略由插件和结果适配器负责，不得静默覆盖已提交最终结果。 |
| 恢复与重新评估 | [Replay](../../examples/Replay.java) 检查输入 SHA 和策略标签，步骤恢复检查定义标签。[会话快照](../../ominicat-conversation/src/main/java/io/ominicat/conversation/ConversationSnapshot.java) 是经过校验的数据，可用新规则评估。 | 外部运行／检查点清单可为恢复绑定定义内容，同时允许以新运行显式重新评估。 |
| 多项目 | 嵌入应用可选择注册表／配置；独立服务器启动时加载一份管线配置，并为每个会话创建新实例。 | 当前通过分开的嵌入绑定或部署实例实现。鉴权、项目路由、凭据、持久化账本和全局配额仍由应用／边缘服务负责。 |
| 资源限制 | 队列、连接、会话、帧／输出字节以及适配器特有的缓冲／截止时间都有边界。 | 需要联合说明与测量这些限制。仅统一配置不能限制 JVM／原生总内存或不可信插件行为。 |

## I1：可选插件描述与兼容性测试用例

触发证据：已安装插件可能在语法上有效，却在接入要求边界前部分转写结果时只提供整段转写。启动预检无法仅凭字符串选项映射确定所有语义能力。

已实现的 I1a 子集新增 `ProcessorDescription`、可选配套接口 `DescribedProcessorFactory`，以及 `PluginRegistry.describe(type, options)` / `requireDeclaredCapabilities(type, options, required)`。现有 `ProcessorFactory` 方法与默认创建行为不变。描述包含可选实现版本，以及有界、带命名空间的 `SUPPORTED` / `UNSUPPORTED` / `UNKNOWN` 声明。缺少描述或能力条目表示**未知**，不是已经验证兼容。显式要求会在开始工作前分别拒绝不支持与未知状态。不新增已验证标志、YAML 字段、线协议字段或 Studio 元数据。

描述按配置查询，不按插件类型缓存。注册表使用不可变选项快照，不调用 `ProcessorFactory.create`。内置转写描述只检查选项名，不解析模型、凭据或端点，也不联系服务提供方。第三方工厂构造器与描述方法必须遵守无 I/O、不泄漏秘密的契约；它们是受信任的 Java 代码，不是沙箱。发现留在绑定边界，不进入帧派发。服务端创建／关闭预检仍独立进行。

内置转写声明支持 `TranscriptionFactory.UTTERANCE_FINALS`，不支持 `TranscriptionFactory.PRE_BOUNDARY_PARTIALS`。后者指显式边界前出现非最终转写，且仍可继续接纳后续 PCM 输入，不是泛化的流式布尔值。接收音频分块、输出 SSE 对话片段或实现 `AsyncProcessor`，均不能单独证明此能力。[能力指南](plugin-capabilities.md)定义了标识与可运行检查。

I1a 验收：

- 在 Java 17、21 和 25 上加载改动前的 Java 17 插件 JAR，无需重编译；创建独立会话状态，并关闭所有拥有的实例。
- 查询声明不调用 `ProcessorFactory.create`、解析凭据或发送供应商请求；ServiceLoader 仍可能实例化工厂本身。拒绝超界描述、空值及工厂类型不匹配，不回显选项值。
- 成功要求已知的整段终稿能力，拒绝已知的边界前部分结果不匹配，并分别拒绝未知声明或缺少能力条目。显式空要求不得创建处理器。
- 用本地脚本化行为探针，区分实际的边界前部分结果后继续输入 PCM，与仅在边界后输出终稿。单靠声明不能产生已验证兼容结果，也不能证明真实 ASR 行为。
- 保留不可变选项／描述快照、独立处理器所有权、默认协议／配置行为，以及未要求能力的旧调用方的普通创建行为。

其余 I1 工作仍在计划中：更丰富的插件／SPI 版本契约、选项 schema、帧／schema 与媒体格式、时间原点、声明限制及下述三类测试。先用当前帧和驱动 API 建立这些基线测试，再由 I2/I3 随 codec／manifest 交付扩展。开放帧契约不能变成所有应用帧的固定枚举。

## I2：选择启用的版本化结果 codec 与溯源引用

触发证据：无关的两个插件可输出同名的自定义帧类。需要持久外部契约的消费者不能依赖该简单类名，也不能假定 Java 成员名永不变化。

在传输／契约边界显式注册带命名空间的 `schemaId` 和结构 `schemaVersion`，保留默认线协议行为与原始帧路径。只注册精确支持的类型／版本，绝不根据客户端提供的名称选择 Java 类或多态反序列化。领域载荷与规则留在插件，不向 core 引入通用结果子类型。

可选结果元数据应引用运行、结果标识、策略／定义标签和内容指纹，并限制证据引用数量。可选的应用限定主体引用可跨会话关联结果，而不合并应用实体模型。应用负责命名空间、对象种类与不透明键的映射；不同命名空间中的相同本地键不得被隐式联结。这些引用不授予访问权，也不授权联结。

结构 schema 版本与策略、提示、模型及流程版本应分开。证据保留媒体时间线、单位与片段修订；不透明媒体引用不得变成无限制嵌入录音。更正通过显式关系指向旧结果，并使用应用定义的归约器，不修改已提交转写。

验收：

- 为两个同名 Java 帧类使用不同 schema ID 编码，拒绝重复 schema 注册与不支持版本。只有显式注册的入站 schema 才能解码。
- 保留 envelope、因果关系、空分数、证据及保留／淘汰范围。未采用新 schema 契约的现有消息保留旧解码行为，包括拒绝未注册的自定义入站类型；默认协议测试用例保持不变。
- 在测试适配器中应用有界更正／撤回事件，验证当前结果且不重复计入旧结果。重试测试使用显式适配器账本；单有结果 ID 不提供持久投递或恰好一次保证。
- 仅通过显式应用主体映射关联独立会话结果。比较完整的 namespace/kind/key 元组：不同命名空间或对象种类下的相同本地键仍彼此独立。实体 schema 和联结授权留在 core 之外。
- 将新 codec 的字节数、分配和序列化成本与内核派发分开测量。限制元数据／证据大小，避免逐帧对大型媒体求哈希。

## I3：运行清单与检查点绑定

触发证据：规则、提示或配置内容变化时，版本标签可能不变。该标签不足以证明是在继续同一次计算。

在外部用版本化清单包装现有快照，包含运行标识、输入指纹、游标、处理器／插件标识、调用方提供的定义／配置指纹和结果 schema 引用。首个实现限定为同步顺序重放；实时流采集和分布式检查点需要独立驱动。模型／提示溯源信息仅在已知时保存；可变模型别名不是固定模型修订。不要序列化 Java 谓词、闭包、emitter、连接或已解析凭据。不可变清单引用可在同一运行中共享，哈希与校验放在创建、恢复和导出边界。

区分两种操作：

- **恢复：** 修改状态前先验证输入、检查点 schema、游标和必需的定义指纹。遇到不支持版本、缺少必需标识或定义变化时，原子拒绝继续。
- **重新评估：** 创建新运行，显式记录与旧输入／运行和新定义的沿袭关系。适当时复用已验证会话数据；底层快照 API 必须继续允许此操作。

验收：

- 在 ID、时钟、规则和输出顺序受控时，确定性同步测试连续执行与恢复后执行应得到等价结果。
- 即使人类可读版本标签未变，输入变化或定义内容变化仍拒绝恢复。恢复失败不改状态；sink 失败不推进驱动游标。
- 使用新规则的重新评估作为新运行成功，并记录沿袭关系。外部模型修订未知时仍保持未知，不能据此建立确定性重放。
- 外部适配器负责快照存储、输出确认、幂等与提交原子性。本契约本身不得暗示崩溃恢复或持久投递。

## 三类测试用例

这些是计划中的验收测试，不是现有端到端产品接入。

其余 I1 工作使用现有 raw/envelope 帧、Replay／窗口 API 和 EvaluationFrame 输出建立基线。I2 增加 schema／归约器互操作检查；I3 增加清单／恢复／重新评估检查。下表描述这些增量合起来的最终覆盖范围；仅有 I1a 声明并未实现这三类测试。

| 类别 | 复用机制／替换方式 | 正向与负向证据 |
| --- | --- | --- |
| 流式事件管线 | 本地异步服务测试、双音轨／声道映射、转写修订／门控、独立会话、envelope 及可选结果 codec。替换 provider／插件／配置，无需分叉 core。 | 验证说话人／角色归属、归一化媒体时间、逐流已提交结果、因果关联、有界队列、取消和过期回调拒绝。驱动必须拒绝未归一化的跨域比较。跨会话复用调用方 ID，测试状态隔离。只有回调调度受控时才重放精确输出，否则应断言文档声明的偏序与取消不变量。 |
| 顺序批量重放 | 现有 JSONL 重放／窗口机制，加上拟议的外部清单与 sink 测试。媒体解码、长文件分段和调度仍由驱动负责。 | 比较不间断执行与检查点恢复，拒绝输入／定义不匹配、记录超限及无效证据时间域。确认 sink 失败保留原游标，所有资源排空。 |
| 跨会话结果聚合适配器 | 通过有界出口消费独立会话的版本化结果，使用显式测试账本、应用限定主体映射和结果归约器。 | 测试重复事件、更正、交付重排、命名空间冲突及 schema 不匹配，避免重复计数或隐式跨应用联结。验证有界批次与显式溢出。内核不承担全局实体注册表、持久账本或跨会话授权职责。 |

三者都复用同一个内核产物，测试配置／插件变化。会话状态和回调隔离是逻辑所有权保证，不是对任意插件的安全沙箱或 CPU／内存隔离。真实 ASR/TTS 行为、模型质量、远程协议故障、生产容量和多设备时钟漂移仍需在目标环境验证。

每类都应注入一次故障：流式处理中的延迟／失败回调，重放中的 sink 失败，聚合中的出口拥塞／重复交付。还要将元数据未知的旧插件与没有 schema ID 的旧消息组合：保留原执行行为，同时明确报告其能力兼容性尚未验证。
