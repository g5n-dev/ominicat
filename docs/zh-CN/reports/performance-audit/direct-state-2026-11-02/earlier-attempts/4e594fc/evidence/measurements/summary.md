# 配对直接调用状态实验

预登记的三个 ABBA 配对块，覆盖七种场景，共运行 84 个全新的单 fork JVM。每个 fork 执行三轮各 1 秒的预热，以及五轮各 1 秒的测量。中间配对块将场景顺序反转。

Ubuntu 24.04.5 LTS；AMD EPYC 7763 64-Core Processor；Java 17.0.21（Eclipse Adoptium）；进程亲和性集合包含 4 个 CPU。使用共享运行器，各场景顺序执行，未进行独占 CPU 隔离。不测量 RSS 或 p99。

观测判定：**uncertain**（结果不确定）。这是实验结果，并非 CI 性能门槛或生产保证。

每个比值均在同一配对块内，以两个候选 fork 均值的平均值除以两个基线 fork 均值的平均值。判定使用全部三个配对块比值；点估计取这三个比值的算术平均值。配对块范围不是置信区间。每侧、每种场景的三十次测量迭代作为六个 fork 内部的观测保留，不视为三十个独立重复样本。

主要场景 raw-direct-4 的分配目标是每个配对块的 B/op 至少下降 10%。所有直接调用场景还要求时间比 ≤1.05、分配比 ≤1.01。如果点估计符合规则，但某个配对块超过限制，则结果判为不确定（uncertain）。未改变的 raw-session-4 路径仅作为阴性对照，不用于校正或覆盖其他结果。

时间必须严格为正。对于分配比，零除以零记为 1（不变）；候选值为正、基线为零时，比值未定义，在 JSON 中保留为 null 并标记 zeroBaselineIncrease，不能满足观测目标。受影响的比值均值和范围均保留为 null，绝不写成 Infinity。因此，直接调用场景出现这种增加时，判定为 targets-not-met，而非技术性采集失败；会话对照仍不参与判定。

全部六个 fork 均值、所有测量迭代、配对块范围及逐项判据见 [summary.json](../../../../../../../../../reports/performance-audit/direct-state-2026-11-02/earlier-attempts/4e594fc/evidence/measurements/summary.json)。时间和分配量均包含共用的正确性判定逻辑及测试驱动。本实验不测量模型/网络延迟、p99、RSS 或 CPU 自身耗时。保留原始 JSON、通过隐私检查的日志、[源代码/产物绑定](../../../../../../../../../reports/performance-audit/direct-state-2026-11-02/earlier-attempts/4e594fc/evidence/measurements/manifest.json)及校验和。技术性采集失败不能成为完整证据；targets-not-met 和 uncertain 仍是完整、可发布的观测结果。
