# 配对会话调用证据 — 2026-11-22

[Ubuntu 运行 44932115058](https://github.com/g5n-dev/ominicat/actions/runs/44932115058) 完成了针对已合并 `SessionInvocation` 改动（[PR #43](https://github.com/g5n-dev/ominicat/pull/43)）的预登记三块 ABBA 实验。按预登记规则，观察判定为 **`uncertain`（不确定）**：所有会话路径的分配与时间目标在每个块中均达标，而两条**未改动**的直接路径控制用例（`audio-direct-4`、`image-direct-4`）各有一个块的时间比超过 1.05——它们在约 29 ns 的测量上分配比精确等于 1.000000，属于共享 runner 对字节相同代码的噪声，不是代码效应。按协议这保持诚实的 `uncertain` 判定；不允许通过事后推理升级。

主用例 `raw-session-4` 的配对分配比为 **0.7027 / 0.7027 / 0.7568**（均值 −27.9%）：592.0 → 426.7 B/op，且每个块的时间比 ≤1.024。`raw-session-1` 分配约降 15%，`raw-session-16` 约降 35.6%；未改动的直接路径分配比保持精确的 1.000000。这些是同一个受控会话调用表示改动、同一探针与配对运行时 JAR 的结果；不构成整框架、模型延迟或生产容量的改进声明。

## 受控源码与行为

两个被测 core 修订（3a71e3f → 84ae2cd，SHA-256 绑定见归档 [manifest](../../../../../reports/performance-audit/session-state-2026-11-22/evidence/manifest.json)）之间只有 `Pipeline.java` 不同。基线在两条会话派发路径上每阶段每帧分配一个 `SynchronousSink` 加一个捕获 continuation 的 lambda；候选只分配单个 `SessionInvocation`，同时承载同步边界、continuation 游标与线程守卫。线程校验、返回后退役、generation 围栏（每个 stage 进入、异步交接与终末输出之前）、null 发射拒绝以及异步 stage 回传会话调度器的路由全部保留；sink 从不池化或重新激活。

合入前行为已确认：419 项测试与 512 个压力种子通过，包括 `interruptsFenceStaleEmissionsAndDropPendingOldTurn` 与 65,536 次操作的内核模型压力 oracle（开发期间正是它们发现并验证了围栏修复）。PR 上的 Java 17 coverage/SBOM 与 Java 17/21/25 兼容性检查均通过。

## 解释边界

会话派发时间（约 7 µs）由队列/worker 交接主导，因此分配收益不转化为时间收益——符合预期，也符合预登记（≤1.05 守卫，观察值 ≤1.024）。分配比精确等于 1.000000 的直接路径控制用例在 29 ns 测量上出现最高 1.107 的单块时间尖峰，是共享 runner 方差，正是协议标注为噪声而非信号的情形。不作任何模型/网络延迟、p99、RSS 或生产容量声明。未来在更安静的主机上重新采集可以升级观察判定；本归档不升级。
