# 配对会话调用状态实验

三个预登记 ABBA 块；七个场景；84 个全新单 fork JVM。每个 fork 有三次 1 秒预热和五次 1 秒测量迭代。中间块反转场景顺序。

Ubuntu 24.04.5 LTS；Intel(R) Xeon(R) 6975P-C；Java 17.0.21（Eclipse Adoptium）；进程亲和集内 4 个 CPU。共享 runner；顺序执行；无独占 CPU 隔离。不测量 RSS 或 p99。

观察判定：**uncertain（不确定）**。这是实验结果，不是 CI 性能门或生产保证。

每个比值将同一块内两个候选 fork 均值的平均除以两个基线 fork 均值的平均。判定使用全部三个块比值；点估计使用其算术平均。块范围不是置信区间。每侧每场景的三十次测量迭代作为六个 fork 内的观察保留，不视为三十次独立重复。

主 raw-session-4 分配目标为每个块至少降低 10% 的 B/op。每个会话场景还目标时间比 ≤1.05、分配比 ≤1.01。若点估计满足规则但某块超限，结果为不确定。envelope-session-4 路径仅作负控制；它不修正或覆盖其他结果。

时间必须严格为正。对分配比，零除以零为 1（未变）；零基线上出现正候选为未定义，保留为 null 并带 zeroBaselineIncrease，且不能满足观察目标。受影响的比值均值与范围保持 null，绝不使用 Infinity。因此直接用例增加会产生 targets-not-met 而非技术采集失败；会话控制保持排除在判定之外。
