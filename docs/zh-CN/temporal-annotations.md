# 时间片段与注释

状态：最小 T1a 引用／导入导出能力已在可选会话模块实现，见 [API 与可执行测试](media-references.md)。T1b、T2 和 T3 仍是设计提案和验收标准，不是已交付的 API、配置字段或线协议类型。本文扩展[接入契约提案](integration-contracts.md)；[场景矩阵](scenario-coverage.md)跟踪已实现范围。

可复用的时间处理需要的不只是文本修订或规则分数。接入可能需要调整区间、拆分或合并片段、附加多个独立注释，并在新证据到达后修订结果。这些契约属于可选模块和适配器，不得把应用实体模型、标签词表或全局状态引入微内核。

只选择接入所需的行为组合。现有原始帧管线和 I1 能力发现不依赖这些契约。只读导入无需编辑器，仅面向主体的注释无需媒体时间线。共享表示不要求共享同一状态机或归约器。

## T1a：最小来源、区间与版本引用

已实现：`MediaReference` 提供有界且不可变的来源／生产者／片段版本引用，明确区间、点和未知位置；`FrameBoundaryMap` 接受驱动提供的整数毫秒边界；`MediaReferenceIO` 提供有界的版本 1 二进制适配器。[使用指南](media-references.md)给出精确限制。这没有增加片段编辑、定位服务或默认线协议扩展。

来源引用标识应用拥有的媒体资产／版本、轨道和坐标基准。应使用带限定范围的不透明引用，而不是嵌入录音、含凭据 URL 或仅本地有意义的文件名。内容指纹由调用方在可用时提供，缺失必须显式表达。大型媒体指纹应在导入／运行边界计算，而不是逐帧计算。

区分来源样本、归一化媒体时间和本地单调处理时间戳。采样区间需要采样率及每通道约定。时钟或音轨之间的对应关系需要显式驱动映射；数值位置或轨道名相同不能证明共享时间线。新能力应明确端点、点事件和未知位置语义，不重新解释旧转写区间。

处理包含末端的离散帧索引时，适配器必须依据声明的帧率／时间基准转换端点。“下一帧”的偏移不能在另一坐标系中任意变成多出一毫秒或一个音频样本。

非均匀帧时间需要驱动提供合适的时间戳／边界映射。若帧从 0/40/100 ms 开始，平均 20 fps 会把帧 1 预测为 50 ms，而实际是 40 ms。仅凭单位或平均速率，不得宣称可精确 seek 或精确转换区间。

对外共享的片段引用包含显式分配作用域、来源绑定、本地片段 ID 与修订。独立分配标识的生产者／运行必须使用不同作用域，即使它们处理同一来源并都输出 `segment-1` 修订 0。适配器可以为旧转写提供已知的本地绑定作用域；现有 Transcript API 不变。作用域是引用数据，不是授权，也不需要内核全局 ID 分配器或查询服务。

验收：

- 两个来源即使轨道名称和数值区间相同，也保持独立。拒绝未提供的时钟映射与不兼容单位。精确 seek 必须拒绝未知位置或已变化的必需来源指纹；位置未知的旧帧仍可用于不要求 seek 的操作。
- 校验 PCM 单位：640 字节的 16 kHz 双声道 PCM16 含每通道 160 个样本，时长 10 ms。不能把字节数或双声道样本总数当作采样游标。
- 区分来自两个生产者绑定的相同本地片段 ID／修订。未限定作用域的外部引用视为未解析，除非适配器提供无歧义的作用域。
- 使用显式 0/40/100 ms 映射精确转换；拒绝仅凭平均速率宣称精确 seek。这不暗示存在自动时钟转换服务。

## T1b：可选的本地片段变更

只有宣称支持编辑的接入才需要这组能力。片段标识与当前区间分开；修订指向精确的先前版本，拆分／合并事件标识所有受影响的父／子版本及操作 ID。变更保留历史引用，不原地修改已提交转写事实。有界、单一拥有者的参考归约器在替换状态前验证整个变更；应用可提供其他符合契约的实现。这种本地原子性不提供持久事务或分布式提交。

所声明编辑操作的验收：

- 中间边界变化时保留显式片段标识。已提交转写仍不可变；叠加修订显式关联旧片段版本和新版本。
- 原子验证拆分／合并：预期修订已过时、子 ID 重复、父版本缺失或声明的沿袭关系无效时，状态不变。定义并测试该操作的重叠／间隔策略，不得全局禁止片段重叠。
- 声明保留窗口内的重复操作不得执行两次。首个实现可立即拒绝冲突；延迟解决是另一项可选能力，须有截止时间和显式溢出。保留范围外的持久去重仍由外部负责。

## T2：独立、版本化的注释

注释具有自己的标识／修订和精确目标：片段版本、点／区间或应用限定主体引用。事件、运行、片段、注释与应用主体标识应分开。完整的主体 namespace/kind/key 元组标识引用，不授权访问或关联。

基础／只读、媒体目标、分组区间与编辑支持分别声明。仅面向主体的注释使用限定主体契约，无需 T1a；媒体目标仅使用所需的 T1a 坐标／引用子集。这些数据能力都不要求 T1b。注释表示可用于进程内；选择拟议的 OminiCat 版本化线协议时，由 I2 提供。其他项目／文件 codec 仍由适配器选择。

表达独立维度和多个有效值，不要把 `speaker`、`role`、规则 PASS/FAIL 或单个汇总分数复用为通用标签。维度／分类体系与载荷 schema 具有显式标识／版本，解释及允许值属于插件。已知时，溯源引用生成它的规则／模型／配置或人工反馈来源；未知置信度或模型修订必须保持未知。

扁平词表是有效选择。类别层级、共享目录和类别到标签的映射都是可选应用元数据；契约命名空间／版本标识解释方式，不强加一种业务分类体系。

编辑、删除或撤回需单独指明 `expectedAnnotationRevision`，不能与证据的 `targetSegmentRevision` 混同。新标签不覆盖其他维度。标签可指向重叠区间或多个显式引用的主体，引用数量有界。父／成员与归属语义属于应用策略，不是通用实体层级。

注释也可指向一组有界的不相交区间，同时保留一个注释标识。跨修订保留这种分组；不能填补间隙、重复赋值，或仅因区间重叠就合并独立注释。维度／值之间的合并兼容性必须是显式插件策略。

生产来源、处理最终性、复核资格与已发布结果有效性应作为独立概念。模型最终输出不会自动成为已批准反馈；已复核注释也不会自动成为当前已发布结论。无效值须产生声明的拒绝、未知标记或显式配置的降级，而不是静默替换成看似有效的值。

每组能力声明其采用的维度、必需字段及省略含义。“未采用某维度”与“已采用但状态未知”不同；省略或通用默认值都不得制造批准、拒绝或有效性结论。

现有项目权限与简单的保存资格可能已经足够。本契约不要求额外复核角色或多阶段审批流程。

验收仅适用于该组能力实际声称的行为：

- 往返保留该能力允许的维度／值，不抹去同一受支持目标上的赋值。媒体／重叠能力还须避免按时间或片段 ID 对不同区间去重。
- 对分组区间编辑，拆分再重组注释时不丢失标识，不改变精确覆盖范围。值／维度不兼容的合并必须按声明策略拒绝，或保留独立赋值。基础点／主体注释无需此操作。
- 标签标识在分类体系／维度命名空间间保持独立；主体标识比较完整 namespace/kind/key 元组。不支持的分类体系／schema 版本明确失败，不静默改写解释。
- 编辑注释时，过时的 `expectedAnnotationRevision` 不能抹去当前注释。明确指向较旧 `targetSegmentRevision` 的引用保留该精确证据目标，不得静默重定向。声明窗口内重复删除幂等；对同一基础版本的竞争编辑按显式策略报告或解决冲突。只读导入器无需变更归约器。
- 人工反馈记录来源和精确目标，但不会自动覆盖模型或发布新的权威结果。权限、复核流程与优先级由应用负责。
- 序列化或扇出前限制维度、值、文本、引用和保留修订。拒绝过大事件和饱和队列，不额外累积无界列表。

## T3：证据依赖与结果生命周期

为计划中的版本化结果扩展来源／片段／注释版本引用、显式依赖及取代／撤回关系。引用保留原时间基准和可用精度。只有完整轮次区间的短摘录，不能被宣称为词级对齐的音频证据。

T3 是对适配器拥有的依赖进行的可选有界投影。依赖引用可共享，但影响、重算与发布策略必须显式。只改边界可能不影响纯文本分数有效性，却要求重新定位音频证据。历史反向索引、跨运行／全局失效图、自动重评调度与持久发布仍由外部负责。

区分比较运行与显式发布的替代结果。重新评估创建新运行，仅因它存在不能使所有旧结果失效。更正依据适配器拥有的影响／发布策略作用于声明的依赖。未能产生替代结果时，不得发布成功的新当前结论。当前结果指针与有效性分开：指针仍可能指向已经标记过时的结果。

证据可用性是第三个独立维度。缓存淘汰报告本地不可用并保留引用标识，本身不得将结果标记过时、撤回结果或声明底层事实已过期。重新加载和长期载荷保留属于外部职责；语义过期需要拥有者的显式策略／事件，而不是内存压力。

所声明依赖／发布行为的验收：

- 应用声明的依赖变化，验证旧结果保留精确引用；片段编辑能力可用拆分／合并作为一例。显式影响策略决定结果是否保持当前、需要重评或被替代。声明依赖不相交的结果不受影响；不同注释维度仍可能共享依赖，并都需要重评。
- 外部来源与结论仍有效时，淘汰缓存证据载荷。保留当前指针／有效性，报告本地不可用，要求显式解析来源，而不是自动撤回结果。
- 测试更正先于原始事件、重复撤回、延迟旧输出和竞争替代。采用显式拒绝或有界延迟策略；仅凭到达顺序不能成为未声明的“最后写入者胜出”规则。
- 对受控发布适配器，若 R0 过时且替代 R1 失败，保留指向 R0 的本地指针及已记录的过时状态，不把 R0 恢复为有效，也不发布 R1。只有到达适配器声明的提交点后才推进本地当前指针。外部 sink 可能先产生作用再抛错，也可能丢失确认；运行时无法撤回已观察到的副作用。若宣称持久幂等或原子发布，需要合适的外部账本／提交协议。
- 异步完成与结果最终性分开。最终／撤回事件不关闭会话；END 不是独立回调的屏障。驱动应等待其拥有的操作／会话对应的完成信号。
- 测试取消、出口拥塞和保留溢出，观测限额与清理；不能凭一次短合成测试宣称生产容量或 JVM 总内存上限。

## 兼容性与交付

为具体测试选择所需的最小能力。已交付的来源／区间导入导出测试建立最小 T1a，无需 T1b/T3。I1 仍独立，仅面向主体的 T2 也可不依赖 T1a。只有声明这些行为的接入才增加分组区间、本地编辑与依赖投影。每个增量都需要合成数据的正例和负例，不存在通用的 T1a → T1b → T2 → T3 强制前置链。

选择拟议的 OminiCat 版本化线协议时使用 I2 注册；其他外部 codec 与文件导入导出不必依赖它。保留默认解码器、旧消息和现有工厂二进制。I1 描述只有在行为探测验证后才能声明支持。I3 检查点绑定须包含相关来源／定义版本，同时继续区分恢复与重新评估。

契约一致性与算法质量需要不同证据。固定窗口分块可用精确边界／单位／连续性和性能断言检查，无需人为附加人工标注语料或 IoU 测试包。学习型／启发式分段插件声明其质量主张，以及相关语料、匹配规则和指标，例如 precision/recall、边界误差或碎片化；这些不是强制的通用套件。人工复核参考资格与发布权限仍是应用决策。合成归约器测试不能证明这些模型／分段分数，吞吐 profile 也不能证明其准确性。

保留 Java 17 和无依赖内核。可选区间／注释／归约器成本分开测量：小载荷与允许的最大载荷、修订和扇出、B/op、吞吐、尾延迟、GC 及排空后保留状态。新的元数据发现、媒体哈希和纯归约器不得将存储／网络 I/O 引入普通内核派发。现有适配器仍可在当前生命周期契约下执行自己拥有的、有界且配合中断的 I/O。存储、授权、来源解码／对齐、领域分段算法、持久账本和全局配额留在适配器与应用。
